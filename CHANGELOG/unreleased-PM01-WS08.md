- fix: the documentation now says what the run-once handlers actually do. Three documents — the handler reference, the storage developer document, and the templates user document — still claimed that editing an `install.sh`, a `Brewfile`, or a rendered template re-runs it, and that `--provision-rerun` is only for re-running content that has *not* changed. dodot has never done that: it reports `older version` and holds, and `--provision-rerun` is exactly how an edit gets applied. The same inverted claim is corrected in the templates skill and in two shipped proposals (#360).
- fix: every handler table lists every handler. `nix`, `external`, and `gate` were absent from roughly a dozen tables and lists that claimed dodot ships eight handlers; it ships ten. The execution-order document additionally claimed each phase holds a single handler, which was never true of `Filter` (three) and stopped being true of `Provision` when `nix` landed beside `homebrew` — that claim is gone, and the honest note that the order within a phase is undefined replaces it (#360).
- change: the handler tables are generated from the registry instead of transcribed. `docs/reference/handler-registry.lex` is rendered from `crates/dodot-lib/src/handlers/catalog.rs` — phase, category, match mode, scope, default patterns and rule priority read straight from `create_registry` and the shipped `[mappings]` defaults — and a test fails when the checked-in page drifts. A new handler now owes the docs one catalog row and a `pixi run gen-docs`, not four hand-edited tables; the handler-authoring guide says so (#360).
- fix: `docs/proposals/shipped/nix.lex` said the content hash is Blake3. It is the first 8 bytes of a SHA-256, rendered as 16 hex characters (#360).
- feat: the `install`, `homebrew`, and `nix` user snippets document what happens when the package manager is not installed — where dodot looks, that it stats rather than spawns, that nothing is recorded and nothing fails, and what `dodot status` says when a receipt outlives the manager that wrote it. The homebrew snippet adds the 5.1.2 version floor and both warning texts, and replaces "macOS-only in practice" with the honest Linux ladder: brew where its prerequisites are acceptable, nix where they are not, `install.sh` where neither fits (#360).
- fix: the nix snippet states plainly that removing a line from `packages.nix` uninstalls nothing — `nix profile remove` appears nowhere in dodot — and names the real homebrew/nix distinction as pinning, written by the user into the manifest, with dodot running `nix profile install --impure` and offering no pinned mode of its own (#360).
- fix: the contributor reference describes the `RunOnceHandler` / `RunOnceCommand` seam. It still documented `InstallHandler` and `HomebrewHandler` as independent structs, which they stopped being when the shared handler landed, and had no section for `nix` at all (#360).
