- feat: the generated init script now records which dodot wrote it (`DODOT_INIT_VERSION`, plus a version field in the heartbeat), and `up`, `down` and `status` all end on a two-line shell-hookup footer: whether dodot is sourced in new shells, and when it last was, by which dodot (#289). This makes **version skew** visible — shells that load a *different* dodot than the one you run, the failure that used to report as "open a new shell" and could never be fixed by one. "Last loaded" now comes from the heartbeat's mtime rather than the generation written inside it, so it reports when a shell last *ran* the script rather than when `up` last wrote it; evidence left by a pre-5.6 dodot reads as `≤5.5.1`; and after `down` (or in a repo where every pack is ignored) the footer says the init script is empty rather than claiming a healthy deployment. The two halves of line two always describe the same activation: when your shell reports one dodot and the heartbeat another, the footer names both events rather than pairing one's timestamp with the other's version. And when `up` or `install --write` starts a shell to check the hookup, that shell now reports the version as well as the generation, so a hookup that loads a current script from the *wrong* binary is measured as skew instead of certified healthy
