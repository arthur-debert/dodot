## 5.7.0 - 2026-08-17

- feat: dodot now asks before an *inferred* dotfiles root can deploy. When `DOTFILES_ROOT` is not set, dodot picks the enclosing git top-level and then the current directory — convenient, but it also means an unrelated repository can look enough like a dotfiles repo to deploy from, which is how a stray `dodot up` can add a shell file to every future session or run an install script you never meant to run. The first mutating command from an inferred root now stops on stderr, names the exact root it resolved and whether git or the current directory chose it, shows handler counts plus up to ten prioritized paths so you can recognize a wrong directory, and asks. Only `y` or `yes` approves; `n`, Enter, anything unrecognized, and EOF all decline, exit 1 with empty stdout, and change nothing. Approval needs a real terminal on *both* sides — piping `yes` in cannot bypass it, and neither can a terminal whose stderr is redirected, because approval must never be accepted for a root you were never shown. Ctrl-C exits 130 and leaves the root untrusted. Approval is recorded before the command runs (it records your choice of path, not whether the deployment succeeded) and never expires (#312).
- feat: `dodot roots list` and `dodot roots forget <path>` inspect and revoke those approvals (#312). Approvals live in one file under dodot's data directory — never in your dotfiles repo, so nothing new is committed — and are keyed by canonical path, so moving a root asks again while replacing its contents in place does not. `roots list` prints each approval in exactly the spelling `roots forget` accepts back, including for a root you have since moved or deleted, and marks a root that is no longer there. There is deliberately no `roots trust`: roots are approved at the prompt or selected outright with `DOTFILES_ROOT`, and a third way in would be a way around the prompt. An approvals file dodot cannot read fails a mutation and is surfaced by `roots list` rather than being read as "nothing approved"; `roots forget` repairs the one case it can, and `dodot reset` remains the recovery route for the rest.
- feat: read-only commands and dry runs stay available on an unapproved root, so `dodot status`, `dodot list`, the probes, and `dodot up --dry-run` still tell you what dodot sees in an unfamiliar repository without authorizing it — and none of them records an approval (#312). A valid `DOTFILES_ROOT` remains the deliberate, non-interactive selection and is never prompted for; a *broken* one now fails naming the bad value instead of quietly falling through to git or the current directory, which used to turn a configuration error into a deployment against a different repository.
- fix: dodot resolves the dotfiles root once per invocation, at one place, and every command uses that value — the CLI, the tutorial, and the library no longer each re-read `DOTFILES_ROOT` and re-run `git rev-parse` with slightly different rules (#312). The resolved root is canonicalized, so a root reached through a symlink (a symlinked `$HOME`, macOS's `/var` → `/private/var`) is recorded in dodot's datastore at its resolved location; deployments made through such a path are relinked on the next `dodot up`.
- feat: the whole protected set now crosses the same gate (#313). `dodot down` from the wrong directory can no longer tear down legitimate deployments; `init`, `fill`, `adopt`, and `addignore` cannot write into a root you never approved; `config set`/`unset` — which persist into the root's `.dodot.toml` — prompt exactly like `up`, while `config list`/`get`/`gen`/`schema` stay open; the repository-local installers (`git-install-filters`, `template install-filter`, `transform install-hook`) and the mutating forms of `refresh` and `transform check` are gated, with `refresh --list-paths` and `transform check --dry-run` remaining trust-free; and the tutorial's real deployment step asks the same question a standalone `dodot up` would, with every narrated step before it read-only. Commands whose writes the root does not select — `install --write`, `git-install-alias`, `prompts reset`, factory `reset`, and the git-filter stdin/stdout passthroughs — deliberately stay outside.
- feat: `refresh` and `transform check` write only sources inside the root that authorized them; a cached baseline whose source belongs to a different dotfiles root is reported (`other root … not touched`) and left alone, so two repos sharing one machine cannot edit each other's files through dodot's shared cache (#313).
- fix: the post-`up` install-ladder and cfprefsd prompts now reuse the exact root the gate authorized for that `up` instead of resolving a second one, so the repository the prompts inspect is always the repository you just approved (#313).
