- fix: every message about a run-once file (`install.sh`, `Brewfile`, `packages.nix`) now names a flag that does what it claims. Three messages in the executor told users to run `dodot up --force` to apply an edited run-once file; `--force` overwrites pre-existing files at symlink targets and re-fetches externals, and re-runs nothing. They now name `--provision-rerun`, matching the handler status path and `--dry-run` (#356).
- fix: after a real `dodot up`, an edited run-once file's row carries a footnote naming the remedy. The row read `older version (3 lines added, 1 removed)` and stopped there: the executor's remedy message rode on a *successful* operation result, and the post-`up` renderer overlays only failures, so it reached no one (#356).
- fix: `dodot up --no-provision` now reports the files it skipped, labelled `skipped (--no-provision)`, in both the real and `--dry-run` renderings. The flag dropped code-execution handlers before intent generation, so the skipped files produced no row at all in a dry run and showed their untouched datastore state in a real one — with no hint the user had asked to skip them. The label stays distinct from a host-gated file's `gated out (…)`: different conditions, different remedies (#356).
- fix: `--no-provision`'s help text said "Skip install scripts and Brewfile". It covers every code-execution handler, `nix` and `external` included, so an `externals.toml` fetch is suppressed along with the rest (#356).
