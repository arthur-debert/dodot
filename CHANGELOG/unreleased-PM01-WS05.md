- feat: a Homebrew too old for your `Brewfile` is now named before the run, not decoded from a parse error afterwards. brew grew `go`, `cargo`, `uv`, `npm`, and `krew` entries one release at a time, the last two in Homebrew 5.1.2, and dodot's own `HOMEBREW_NO_AUTO_UPDATE` stops brew from quietly updating itself past that line — so `dodot up` asks `brew --version` before running the bundle and reports a brew below 5.1.2 with `brew update` as the remedy. It reports rather than refuses, and hedges: dodot does not read your `Brewfile`, so it says one of those entry types may fail rather than that all of them will — a 5.0.16 already handles `go`, `cargo`, and `uv`, and a file of plain `brew` lines runs fine on an installation older still. A brew at or above the floor says nothing (#359).
- change: the version question is asked only by `dodot up`, only for a `Brewfile` that is actually about to run, and once per machine per run however many packs declare one. `dodot status` and `dodot up --dry-run` still spawn nothing at all — they answer "is brew here?" from the filesystem, which is what keeps them free to run (#359).
