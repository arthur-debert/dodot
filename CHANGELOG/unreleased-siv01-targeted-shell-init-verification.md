- feat: ordinary `dodot probe shell-init`, `dodot install --write`, and the verification that `dodot up` performs when activation evidence does not establish a current hookup now measure whether a newly started interactive shell reaches dodot's hook, rather than waiting for the whole rc file to finish. A fresh process-bound challenge lets a current file-source or `eval "$(dodot init-sh)"` hook answer with its generation and dodot version, then exits the verification shell before heartbeat or profile writes, PATH and Homebrew setup, pack contributions, or later rc work. All three commands now report the same reached-current, version-skew, generation-skew, inconclusive, timeout, and spawn-error outcomes. After an answer or timeout, dodot terminates and reaps the verification shell's process group so descendants and inherited output pipes cannot keep the command alive (#327, #329, #337).
- feat: full PATH-at-the-hook diagnosis is now an explicit `dodot probe shell-init --trace-hook` operation; the bare command performs only the targeted time-to-hook check. Current diagnostic-capable hooks suppress heartbeat and profile writes while tracing continues through PATH setup, Homebrew, pack contributions, and later rc work, so commands in the rc can still have their normal side effects. A capability-unknown legacy hook instead uses a faithful temporary rc copy, records PATH immediately before the hook, and exits without executing the hook or later rc work. Diagnostic-capable eval hooks can start the rc up to three times for target discovery, the primary trace, and a temporary-copy fallback; file-source hooks need at most two starts (#330, #337).
- fix: `dodot probe shell-init` no longer presents an interrupted timing profile as the latest completed startup. The default report skips newer incomplete records and selects the newest completed run, or says that no completed profile exists. `--history` still lists incomplete runs, preserves every file row completed before interruption, labels the run `incomplete`, and reports its whole-run total as `unknown` because no closing timestamp was recorded (#328, #337).
- fix: passive shell-init views remain passive: `dodot status`, bare `dodot install`, `dodot probe shell-init --no-verify` (and deprecated `--no-trace`), file filters, `--runs`, `--history`, and `--errors-only` do not start a shell or alter activation evidence. Results where no live measurement was attempted now report an unavailable duration instead of claiming the operation took `0 µs` (#327, #330, #337).
