- fix: `dodot adopt ~/.config/zed/` no longer refuses the whole directory because it holds a `.DS_Store`. A child matching `[pack] ignore` is the noise you already told dodot to leave alone, so adopt now leaves it a real file at its original path, adopts every other child, and reports it once — with the pattern that matched and the configuration file that supplied the list. Naming that path yourself is still refused: adopting it would put an entry in your pack that no later `dodot up` or `dodot status` reads (#376).
- fix: `dodot adopt` reads `[pack] ignore` the way a pack scan does. It used to test a source against the root list *concatenated* with the destination pack's, so a pack whose `.dodot.toml` re-listed the defaults minus one pattern was still refused on a pattern no scan of that pack would apply. A pack-level list replaces the inherited one, and adopt now classifies against that single effective list — the same one `dodot up` applies to that pack — and names which layer supplied it (#376).
- fix: `dodot adopt ~/.config/nvim/.luarc.json` is refused instead of silently producing an unreadable pack entry. A pack's top-level scan skips every name starting with `.` except `.config`, so adopting one used to move the file into the pack and symlink the original at an entry no dodot run reads. A hidden child found while expanding a directory is left where it is and reported, like an ignored one; the refusal for a named one says outright that no config setting changes the rule, because none does (#376).
- change: `dodot adopt` refuses a `.dodot.toml` or `.dodotignore` whether you name it or it turns up expanding a directory. Copying either into a pack would replace that pack's configuration or hide the pack entirely, which is not something to do as a side effect of adopting a directory. When a path matches both this rule and the hidden-name rule, the message is about the reserved name (#376).
- change: `dodot adopt` refuses a directory whose children are all skipped by a discovery rule — including an empty one — and lists each child with the rule that matched it. Reporting every child as left in place and exiting `0` would claim an adoption that never happened (#376).
- change: adopt classifies only where a pack scan reads a name: the first component of the in-pack path, plus the first component inside a `--only-os` directory that passes on this host, since a passing gate directory surfaces its children at pack-root level. `dodot adopt ~/.config/nvim/lua/plugins/init.lua` is refused when `lua` matches a pattern and proceeds when `plugins` or `init.lua` does. Routing prefixes (`_home/`, `_xdg/`, `_app/`, `_lib/`) are ordinary names at that position, so `_home/.gitconfig` and `lua/.hidden.lua` adopt normally. `[mappings] ignore`, `[mappings] skip`, and gate labels dodot defines never participate — they route a file the scan did read; a `_<label>` directory naming a label nothing defines does participate, because a scan fails on it rather than routing it. `--force` changes none of these outcomes (#376).
- fix: `dodot adopt ~/.config/node_modules/settings.json` no longer publishes a pack that later runs skip. The pack directory is a scanned position too — `dodot up` and `dodot status` start by scanning your dotfiles root, and that scan drops directory names matching the root `[pack] ignore` list, names starting with `.`, and names outside the pack-name grammar. Because an inferred pack name comes from the source's own path, adopt could land on one of those and replace your file with a symlink into a pack nothing reads. It now refuses before writing, names the rule, and points at `--into <pack>` (#376).
- fix: `dodot adopt ~/.config/nvim/_bogus/init.lua` is refused instead of breaking the pack it lands in. A pack scan doesn't skip a `_<label>` directory whose label nothing defines — it stops on it, and that error fails the scan of the whole pack, so adopting one would make every later `dodot up` and `dodot status` fail on a pack that read fine before. Found while expanding a directory, it's left in place and reported like an ignored child; defined gate labels and routing prefixes are unaffected (#376).
