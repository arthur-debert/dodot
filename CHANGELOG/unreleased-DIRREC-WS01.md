- fix: `dodot adopt` no longer leaves a pack behind for a run it then refuses. Adopting into a pack the path implies — `dodot adopt ~/.config/ghostty/config` for a pack `ghostty` that does not exist yet — used to create the pack directory first and check afterwards, so a cross-pack conflict, an unreadable source, or an ignored filename left an empty pack the user never asked for. Every refusable check now runs before anything is written, prospective content is staged in a hidden `.dodot-adopt-` directory inside your dotfiles root (which pack discovery skips, so a concurrent `dodot status` sees your packs and not a half-copied one), and the pack is published with a single rename: it appears complete or does not appear (#375).
- fix: `dodot adopt --dry-run` for a pack that does not exist yet writes nothing. It used to create the pack directory and leave it there; it now reports the plan it would carry out and removes its staging directory (#375).
- change: `dodot adopt` refuses an invocation that names a directory and something inside it — `dodot adopt ~/.config/nvim/lua ~/.config/nvim/lua/init.lua` — instead of adopting both. No order of publication comes out right for that pair: replace the directory first and the file resolves back into the pack through the new symlink; replace the file first and publishing the directory buries it. Adopt the outer path alone — adopting a directory already carries its contents (#375).
