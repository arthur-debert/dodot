[header]dodot secret[/header] — Inspect secret providers and template references.

[desc]Two read-only commands for checking the secrets layer without
running [item]dodot up[/item]. Both are advisory and safe: they never resolve a
secret, never decrypt, never prompt for passwords or keystore unlocks.

[item]secret probe[/item] runs a health check on every provider configured under
[item][secret][/item] and reports one row per provider: [item]ok[/item], [item]not_installed[/item],
[item]not_authenticated[/item], [item]misconfigured[/item], or [item]probe_failed[/item]. Always
exits 0 — a failing provider lineup is information, not an error.

[item]secret list[/item] scans every pack's templates for [item]secret(...)[/item] calls and
reports one row per call. Useful before the first [item]dodot up[/item] on a new
machine to inventory which providers a repo expects. Encrypted
sources are not scanned ([item]list[/item] does not decrypt).[/desc]

[header]USAGE[/header]
  [usage]dodot secret probe[/usage]
  [usage]dodot secret list[/usage]

[header]EXAMPLES[/header]
  [example]dodot secret probe             [dim]# is my secrets setup healthy?[/dim]
  dodot secret list              [dim]# every secret(...) call in the repo[/dim]
  dodot secret probe --output json | jq '.rows[] | select(.state != "ok")'[/example]
