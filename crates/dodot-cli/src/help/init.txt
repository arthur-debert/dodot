[header]dodot init[/header] — Create a new pack.

[desc]Creates a directory with the given name in your dotfiles root
containing a commented [item].dodot.toml[/item] — and nothing else. Bare-bones by
design: to add starter handler files ([item]install.sh[/item], [item]aliases.sh[/item], a
[item]Brewfile[/item]), run [item]dodot fill <pack>[/item] afterward.

After [item]init[/item], [item]dodot status <pack>[/item] is the right next step — it shows
what dodot would do with the pack as-is.[/desc]

[header]USAGE[/header]
  [usage]dodot init <PACK>[/usage]

[header]ARGUMENTS[/header]
  [item]<PACK>[/item]   [desc]Name of the new pack (becomes the directory name)[/desc]

[header]EXAMPLES[/header]
  [example]dodot init nvim
  dodot fill nvim                [dim]# optional: add starter handler files[/dim]
  dodot status nvim              [dim]# see what dodot would do with the new pack[/dim][/example]

[header]SAFETY LOCK[/header]
  [desc][item]init[/item] writes inside the selected root, so its first use on an implicitly
  discovered, unapproved root asks for approval before creating the pack. A
  non-interactive invocation refuses. For automation, set a valid
  [item]DOTFILES_ROOT[/item] explicitly. Read-only [item]list[/item] / [item]status[/item] remain
  available without approval. Inspect or revoke approvals with [item]dodot roots[/item].[/desc]

[header]SEE ALSO[/header]
  [item]dodot fill[/item]    [desc]Add starter handler files to an [item]existing[/item] pack[/desc]
  [item]dodot adopt[/item]   [desc]Move a file from your home dir into a pack[/desc]
  [item]dodot status[/item]  [desc]Confirm what the new pack will deploy[/desc]
