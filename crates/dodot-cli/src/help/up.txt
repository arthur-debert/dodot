[header]dodot up[/header] — Deploy packs.

[desc]Reads each pack, claims files according to the handler conventions, and
materializes the result on disk: symlinks for configs, [item]source[/item] lines
queued for the shell init script, [item]bin/[/item] directories registered on [item]$PATH[/item],
and one-shot [item]install[/item] / [item]Brewfile[/item] / [item]packages.nix[/item] commands run the first
time dodot sees them.

The pack you deployed yesterday will skip its install script today — a
recorded run keeps it from running again. Editing the script does not
change that: [item]up[/item] reports the file as [item]older version[/item] and holds it. Use
[item]--provision-rerun[/item] to apply the new content, or [item]--no-provision[/item] to
skip these handlers entirely on a given run.[/desc]

[header]USAGE[/header]
  [usage]dodot up [OPTIONS] [PACKS...][/usage]

[header]ARGUMENTS[/header]
  [item]<PACKS>...[/item]   [desc]Packs to deploy. Empty means every discovered pack.[/desc]

[header]OPTIONS[/header]
  [item]--dry-run[/item]              [desc]Preview the run without making changes[/desc]
  [item]--no-provision[/item]         [desc]Skip every code-execution handler this run: install, homebrew, nix, external (still does symlink/shell/path)[/desc]
  [item]--provision-rerun[/item]      [desc]Re-run install / Brewfile / packages.nix even if their content hash matches[/desc]
  [item]--force[/item]                [desc]Overwrite pre-existing files at target locations[/desc]

[header]EXAMPLES[/header]
  [example]dodot up                       [dim]# deploy every discovered pack[/dim]
  dodot up git nvim              [dim]# deploy specific packs[/dim]
  dodot up --dry-run             [dim]# show what would change[/dim]
  dodot up --no-provision        [dim]# skip install, brew, nix and external fetches[/dim]
  dodot up --provision-rerun     [dim]# apply edited install / brew / nix content[/dim]
  dodot up --force git           [dim]# overwrite conflicting target files[/dim][/example]

[header]NOTES[/header]
  [desc]Configuration handlers ([item]symlink[/item], [item]shell[/item], [item]path[/item]) are idempotent and
  always run in full. Run-once handlers ([item]install[/item], [item]homebrew[/item], [item]nix[/item]) run
  once per file and then stop; editing the content does not re-run
  them, it makes [item]up[/item] report [item]older version[/item] and wait for
  [item]--provision-rerun[/item]. [item]external[/item] decides for itself: it re-fetches when
  the declared sha256 or the upstream commit moves. [item]--no-provision[/item]
  drops all four for one run; their files still appear in the output,
  labelled [item]skipped (--no-provision)[/item].

  After [item]up[/item], shell snippets and PATH additions take effect in shells
  that re-source the init script. Open a new shell, or source it
  manually.

  [item]up[/item] also reports whether any shell is actually loading dodot. If
  it says no shell has, run [item]dodot install --write[/item] — that wires the
  hook and verifies it by starting a shell.[/desc]

[header]SAFETY LOCK[/header]
  [desc]Before the first root-sensitive mutation on an implicitly discovered,
  unapproved root, dodot asks you to approve the canonical path. A
  non-interactive invocation refuses instead. For automation, set a valid
  [item]DOTFILES_ROOT[/item] explicitly. [item]up --dry-run[/item] bypasses the gate and
  records no approval. Inspect or revoke approvals with [item]dodot roots[/item].[/desc]
